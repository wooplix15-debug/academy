# ZDV-M12 Developer defense and handover
Version 0.2 | Team review required | Synthetic teaching case

## Purpose
- Explain implementation tradeoffs
- Transfer support knowledge

## Prerequisite and capstone contribution
Use the previous module evidence as input: ZDV-M11

Save this module evidence in the same course portfolio: Portfolio bundle and final practical.

## Explain the concept
The developer defense tests code comprehension and repair skills. A prepared demo is supplemented with a new input and an operator handover task.

## Demonstration and sample input
Reviewer changes the request key policy and asks the learner to explain migration implications before editing. A second developer then follows the pending-sync runbook.

## Live teaching sequence
- Retrieve prior learning: 15 minutes
- Explain and predict: 30 minutes
- Trainer demonstration: 35 minutes
- Guided build: 75 minutes
- Break: 15 minutes
- Failure and recovery tests: 40 minutes
- Evidence review and exit check: 30 minutes

## Guided lab
1. Package source, dictionary, contract and test results.
2. Demonstrate the ten required scenarios.
3. Explain one failed test and repair.
4. Answer a new conflict scenario.
5. Ask a peer to reconcile one pending request using only the runbook.

## Expected result
Learner independently explains ownership and replay decisions. Peer completes reconciliation with no secrets in the bundle.

## Negative test
The reviewer asks whether local SQLite success proves live CRM race behavior. The answer must state the simulation boundary.

## Recovery test
Repair one failed support step and repeat the peer exercise.

## Independent practice
Create a client-neutral portfolio explanation with sanitized screenshots and limitations.

Budget: 120 minutes. Use 15 minutes planning, 75 building and testing, 30 documenting.

## Submit and assess
Portfolio bundle and final practical.
- Learner explains code independently
- All required tests pass
- Handover includes limitations and maintenance

## Learner reflection
What distinguishes a defensible portfolio from a screenshot collection?

Describe one failed input, your correction and evidence that the correction worked.
