# AAB-M01 AI use cases and limits
Version 0.2 | Team review required | Synthetic teaching case

## Purpose
- Select a measurable automation use case
- Distinguish generation from deterministic execution

## Prerequisite and capstone contribution
Start the course capstone evidence folder and record the training environment.

Save this module evidence in the same course portfolio: Use case scorecard and baseline.

## Explain the concept
Choose AI for tasks where generated language is useful and review is feasible. Deterministic calculations and irreversible operations need explicit logic and ownership.

## Demonstration and sample input
Compare lesson-outline drafting, attendance arithmetic and automatic certificates. Select lesson drafting for the pilot; calculate attendance in code; leave certificate decisions with the authorized reviewer.

## Live teaching sequence
- Retrieve prior learning: 15 minutes
- Explain and predict: 30 minutes
- Trainer demonstration: 35 minutes
- Guided build: 75 minutes
- Break: 15 minutes
- Failure and recovery tests: 40 minutes
- Evidence review and exit check: 30 minutes

## Guided lab
1. Score three uses for value, input readiness and failure consequence.
2. Define one named user.
3. Time three baseline drafts.
4. Select a bounded output.
5. Write what requires human verification.

## Expected result
A use-case brief includes baseline units, quality criteria, reviewer and scope. Any time saved is a hypothesis until a controlled pilot measures it.

## Negative test
Request a guaranteed legal or technical answer without source material. Mark the dependency instead of expanding the claim.

## Recovery test
Narrow the task to an outline with explicit gaps and remeasure review effort.

## Independent practice
Compare a corporate support-summary use case with lesson drafting using the same scorecard.

Budget: 120 minutes. Use 15 minutes planning, 75 building and testing, 30 documenting.

## Submit and assess
Use case scorecard and baseline.
- Task has a clear user
- Failure consequence is stated
- Baseline work can be measured

## Learner reflection
Why measure review time as well as generation time?

Describe one failed input, your correction and evidence that the correction worked.

## Source verification
Official reference IDs: S07, S08. Verify the current edition, account metadata and API signature before a live product demonstration. Examples and thresholds are proposed lab rules.

## Trainer preparation
Use the separate trainer key. Rehearse the positive, negative and recovery case. Provide a mock equivalent if required product access is unavailable; label the evidence accordingly.
